Technical Documentation · Software

614 One – document review by NAHX Technologies

Web app that pre-reviews Word and PDF documents against rule sets and produces reports in four languages. First pilot customer and tester is FSH Documentation.

Flow

  1. Upload document
  2. Choose rule sets
  3. Review with locations
  4. PDF report (de/en/uk/ru)
Starting point
Technical documentation has to be checked against basic requirements, DIN EN IEC/IEEE 82079-1 and CE conformity rules. This was done manually, with checklists, and differently by each reviewer.
Challenge
A pre-review that is repeatable, cites locations, supports several users with their own settings and delivers reports customers can read in their language.
My contribution
Design and development of the web app: architecture, review logic, accounts and roles, reports, tests, operating instructions for the Mac. Trialled in a pilot with FSH Documentation.
Approach
Rule sets as verifiable JSON files (24 rules with area, weight and recommendation in de/en/uk/ru), keyword search with score and traffic light, rules that can be deselected per account, reports as PDF. Expert review and approval explicitly stay with a person; every report says so.
Technologies
Python, FastAPI, Uvicorn, SQLite, python-docx, pdfplumber, ReportLab, Argon2 for passwords, pytest; interface without a framework.

StatusRunning with test coverage (accounts, review, languages, command line). In pilot use with FSH Documentation as first customer and tester; screenshots and access are not public yet.

Jersey Wall – interactive squad page for a floorball club

Custom web module: jerseys on a rail, player card with jersey animation and editing via an admin page, no libraries.

Flow

  1. Edit kader.json (admin)
  2. Validation
  3. Squad page with jerseys
  4. Publish via token
Starting point
A floorball club wanted to present its squad on the website: jerseys on a rail, player card with data, maintenance without programming skills.
Challenge
An animation after a video reference that runs on phones, data the club maintains itself, and a bilingual interface (German, Ukrainian).
My contribution
Concept, implementation, data model, admin page, publishing interface, review report with status per finding and handover note for integration.
Approach
Plain HTML, CSS and JavaScript without a build step; all data in one JSON file with validation (required fields, unique IDs); jerseys as generated SVG; animation only via transform and opacity, respecting prefers-reduced-motion; small Python server with token-protected publishing and photo upload.
Technologies
HTML, CSS, JavaScript (no framework), JSON, SVG, Python standard library for the server, Oswald (OFL) for the jersey print.

StatusModule finished and reviewed (review report of 8 Oct 2026 worked through). Integration into the existing club website prepared; club name only after approval.

Software & Web Applications · Automation

Website relaunch and weekly SEO audit

Static website from JSON content plus an automated audit routine with PDF reports.

Flow

  1. Content as JSON
  2. Build and checks
  3. Static pages
  4. Weekly audit with PDF
Starting point
A technical documentation service provider had an outdated site built with a site builder, without clean metadata, sitemap or any way to verify it.
Challenge
A website that can be maintained without an agency, is checked automatically on every build and whose visibility is monitored continuously.
My contribution
Site plan, content as data, build system with checks, legal-text review package for the lawyer, DNS and email checks, audit routine with reports.
Approach
Build in Python without packages: content as JSON, output as static HTML with title, description, canonical, Open Graph, JSON-LD, sitemap; checks for headings, links, anchors and alt texts. A weekly audit checks availability, on-page factors, SPF/DMARC and the search index, writes JSON and two PDFs and compares with the previous run.
Technologies
Python (standard library), HTML/CSS, JSON, Chromium via Playwright for rendered pages and PDF reports, GitHub Actions for build and Pages, Markdown.

StatusWebsite built and verified; go-live is with the operator (domain, legal texts). The audit runs weekly and automatically. Operator name after written approval.

Automation & AI

Mail triage and daily round (own tool)

Daily inbox sorting with a proposal table, release word and a local model.

Flow

  1. Read mail (read-only)
  2. Proposal table
  3. Release word
  4. Move and log
Starting point
My own inbox mixes customer mail, receipts, newsletters and advertising. Sorting cost time every morning and was done inconsistently.
Challenge
Automation that does nothing on its own: no sending, no deleting, no moving without explicit release, and confidential content stays on the machine.
My contribution
Design of the workflow rules, scripts, block list, logging, scheduling, tests with stubs.
Approach
Apple Mail is only read via AppleScript; a proposal table assigns each mail to a target folder; moving happens only after the exact release word, and the script re-checks sender and subject before every action. Unclear cases always stay put. Knowledge questions are answered by a local model via Ollama, offline.
Technologies
Shell (zsh), AppleScript, launchd for scheduling, Claude Code as interface, Ollama with a local model, Markdown for logs.

StatusIn daily personal use since September 2026. Shows what AI support with fixed checkpoints looks like.

This website

Bilingual static site with its own build system, checks and vector logo.

Flow

  1. de.json / en.json
  2. build.py with checks
  3. dist/ (static)
  4. Host
Starting point
NAHX Technologies needed a presence that works without external services, tracking or form back ends and can be maintained permanently by myself.
Challenge
German and English in full, a logo as a true vector from a raster template, domain still open, no invented details.
My contribution
Everything: concept, copy, design system, build system, logo reconstruction, checks.
Approach
Content in two JSON files with identical keys, build in Python without packages, checks for language tags, headings, metadata, links and anchors; without a base URL, canonical, hreflang and sitemap are deliberately omitted. Logo measured from the template and rebuilt as SVG paths.
Technologies
Python, HTML/CSS without a framework, SVG, local fonts (OFL), Playwright for rendering and link checks.

StatusYou are reading it. Open: domain, legal notice details, approvals for references.
