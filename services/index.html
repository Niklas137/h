Technical Documentation

Prepare technical content so that it is understandable, structured and verifiable. This covers new documents as well as revising existing material and the workflows behind it.

Typical challenges

  • Documents have grown over time; structure and terminology are inconsistent.
  • Review and approval steps are undefined or not traceable.
  • Content is scattered and maintained in several places.

Services

  • Creation and revision of technical content
  • Documentation structuring and quality assurance
  • Support for editorial review processes
  • Improvement of documentation workflows

Use cases

  • A manual is restructured and its terminology unified.
  • A document review workflow is defined and backed by checklists.
  • Scattered content is moved into a reusable structure.

Useful for technical companies, development teams and service providers that create, review or hand over documentation.

Software & Web Applications

Digital tools that simplify a specific task: from an internal helper to a web application with accounts and reports. Concept, implementation and ongoing development from one source.

Typical challenges

  • A process runs on spreadsheets, emails and shouting across the room, and is error-prone.
  • An idea should become tangible as a prototype before investing.
  • An existing application must be extended or connected to an interface.

Services

  • Design of custom digital tools
  • Development of web applications and internal tools
  • Prototyping and MVP development
  • Data processing, interfaces and improvement of existing solutions

Use cases

  • An internal tool replaces a spreadsheet and makes states traceable.
  • A prototype shows within weeks whether an approach holds.
  • A web application turns structured input into verifiable reports.

Useful for teams with a clear need but no in-house development.

Automation & AI

Identify recurring work and automate it where it pays off. AI is used when it brings a traceable benefit, for example when evaluating documents, not as an end in itself.

Typical challenges

  • Recurring steps cost time and are done inconsistently.
  • Information is buried in documents and has to be extracted manually.
  • An AI approach should be tested without handing out data uncontrolled.

Services

  • Analysis of repetitive workflows
  • Design and implementation of practical automation
  • AI-assisted information and document workflows
  • Prototyping and technical validation

Use cases

  • A document review step is partly automated; the result stays traceable.
  • Incoming documents are pre-sorted and summarised; the decision stays with a person.
  • A local AI approach is tested where data does not leave the premises.

Useful for organisations with recurring information and document tasks.

What I work with

What is actually in use in the projects.

Languages and runtime

  • Python (FastAPI, standard library, pytest)
  • JavaScript without a framework, HTML, CSS, SVG
  • Shell (zsh), AppleScript, launchd

Documents and data

  • Reading Word and PDF (python-docx, pdfplumber), PDF reports (ReportLab, Chromium)
  • JSON as content and rule format with validation
  • Markdown and Git for logs, knowledge and versions

Checking and automating

  • Playwright/Chromium for rendering, link and layout checks
  • GitHub Actions for build and publishing
  • Claude Code as working environment, local models via Ollama when data must not leave the premises

Not every challenge requires new software.
